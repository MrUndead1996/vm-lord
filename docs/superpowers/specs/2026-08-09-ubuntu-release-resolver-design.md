# TASK-53: резолвер релизов Ubuntu

Дизайн резолвера: по версии дистрибутива получить URL официального cloud-образа
и его SHA256, разобрав опубликованный рядом файл контрольных сумм. Часть
декомпозиции эпика #48 «Импорт cloud-образов»; опирается на #50 (загрузка образа
с кешем), результат резолвера — вход для `fetch_image`.

## Задача

Загрузчик из #50 умеет скачать образ по URL и проверить его сумму, но и то и
другое ему кто-то должен сообщить. Сегодня это никто: URL официальных
cloud-образов Ubuntu строится из версии по фиксированной схеме, а сумма лежит в
`SHA256SUMS` в том же каталоге. Резолвер закрывает этот разрыв.

Вызывающего у него, как и у загрузчика, пока нет: импортёр (#52) появится позже,
а каталог с выбором релиза эпик прямо выносит за скобки. Поэтому в объём входит
функция резолва и профиль дистрибутива, но не UI и не оркестрация «резолвни и
скачай» — последняя составляет три строки на стороне того, у кого появится
вызывающий, и заводить её без него значит гадать о его потребностях.

## Что делает AppSandbox

Ничего сопоставимого. `prefetch_build_deps.c` тянет пакеты с захардкоженных
адресов по plain HTTP; понятия «релиз дистрибутива» там нет вовсе. Заимствовать
нечего.

## Факты, проверенные на живом сервере

Эти четыре пункта подтверждены запросами к `cloud-images.ubuntu.com` и запуском
`ureq` до написания спеки. Они несущие: на них стоят решения ниже.

1. `https://cloud-images.ubuntu.com/releases/24.04/release/SHA256SUMS` отвечает
   **302** на `.../releases/noble/release/SHA256SUMS`. Номер версии
   резолвится в кодовое имя **сервером**.
2. `ureq` идёт за этим редиректом сам: итоговый статус 200, тело 7843 байта.
   Проверено тестом на настоящем сервере.
3. Имя файла в каталоге релиза содержит **номер версии**, а не кодовое имя:
   `ubuntu-24.04-server-cloudimg-amd64.img`. Проверено на 24.04 и 22.04.
4. `body_mut().with_config().limit(n).read_to_string()` при превышении потолка
   даёт `Err` с текстом `the response body is larger than request limit: n`, а
   не молча урезанное тело.

Формат `SHA256SUMS` — строки `<64 hex><пробел>*<имя файла>`, звёздочка означает
бинарный режим. В боевом файле около сотни строк на все архитектуры и все
форматы образов.

## Границы модулей

Три новых модуля в существующем крейте `crates/image`:

* `distro.rs` — `DistroProfile`, константа `UBUNTU`, проверка формы версии,
  сборка URL образа и URL файла сумм.
* `checksums.rs` — разбор `SHA256SUMS`.
* `resolve.rs` — `resolve_image`: единственная функция, ходящая в сеть.

`ResolveError` кладётся в существующий `error.rs`, рядом с `DownloadError`.

Новый крейт не заводится: `ARCHITECTURE.md` уже фиксирует, что резолвер релизов
и qcow2-ридер живут в `vmlord-image`, и резолвер пользуется его `build_agent` —
тем же клиентом с платформенным верификатором сертификатов и таймаутами, что и
загрузка.

## Профиль дистрибутива

```rust
pub struct DistroProfile {
    pub name: &'static str,                 // "Ubuntu"
    pub directory_template: &'static str,   // ".../releases/{release}/release/"
    pub file_name_template: &'static str,   // "ubuntu-{release}-server-cloudimg-amd64.img"
    pub checksum_file: &'static str,        // "SHA256SUMS"
    pub default_user: &'static str,         // "ubuntu"
    pub admin_group: &'static str,          // "sudo"
}

pub const UBUNTU: DistroProfile = DistroProfile {
    name: "Ubuntu",
    directory_template: "https://cloud-images.ubuntu.com/releases/{release}/release/",
    file_name_template: "ubuntu-{release}-server-cloudimg-amd64.img",
    checksum_file: "SHA256SUMS",
    default_user: "ubuntu",
    admin_group: "sudo",
};
```

Профиль — таблица данных, а не трейт с реализацией на дистрибутив. Ubuntu и
Fedora различаются шаблоном URL, дефолтным пользователем, админской группой и
именем файла сумм — это поля, а не поведение; пять структур, различающихся
константами, — ровно тот случай, про который AGENTS.md пишет avoid unnecessary
abstractions.

Вариативность разбора при этом **не** выносится в поле профиля.
`checksum_file: &'static str` называет файл, а разбирает его прямой вызов
`parse_sha256sums`. `enum ChecksumFormat` с единственным вариантом и `match` с
единственной веткой не различают ничего и являются той же мёртвой абстракцией,
только в enum-обёртке. Когда придёт Fedora со своим `.CHECKSUM`, рядом появится
второй парсер и enum с двумя настоящими вариантами — правка на десяток строк.
Указатель на функцию разбора в поле профиля отвергнут: это полиморфизм под видом
данных, читается хуже enum'а и не даёт ничего сверх него.

Шаблон URL хранится **двумя частями** — каталог и имя файла. `SHA256SUMS` лежит в
том же каталоге, что и образ, и при одном сплошном шаблоне пришлось бы вырезать
из него хвост, чтобы получить каталог.

Архитектура зашита в шаблон имени константой `amd64`, отдельного поля нет:
Hyper-V у нас x86_64, а поле с единственным возможным значением — то же самое,
что и enum с единственным вариантом.

Подстановка — замена литерала `{release}` в обоих шаблонах. Никакого движка
шаблонов: одна подстановка одного ключа.

## Вход

Единственный аргумент, кроме профиля, — версия строкой (`"24.04"`).

Форма проверяется жёстко: две или три цифры, точка, две цифры, и ничего больше.
Строка подставляется прямо в URL, то есть это attacker-influenced input в том же
смысле, в каком им было расширение из URL в `cache_file_name`
(`crates/image/src/cache.rs:52-66`): без проверки `../..` уводит запрос в чужой
каталог того же сервера.

Кодовые имена (`noble`, `jammy`) как вход не принимаются. Сервер сам редиректит с
номера на кодовое имя (факт 1), так что таблица соответствий в коде не нужна
вовсе — а её отсутствие означает, что новый релиз Ubuntu работает без правки
кода. Принимать оба вида значило бы завести два разных написания одного и того
же релиза, дающих разные имена файлов (факт 3).

## Результат

```rust
pub struct ResolvedImage {
    pub url: String,
    pub sha256: String,               // hex, нижний регистр
    pub default_user: &'static str,
    pub admin_group: &'static str,
}

pub fn resolve_image(profile: &DistroProfile, release: &str)
    -> Result<ResolvedImage, ResolveError>;
```

`sha256` отдаётся в том виде, какого ждёт `ImageDownloadRequest::expected_sha256`,
так что вызывающий склеивает одно с другим без переходника.

Гостевые поля (`default_user`, `admin_group`) едут в результате, а не достаются
из профиля отдельным обращением: они понадобятся cloud-init'у в #3, и объяснять
второй раз, откуда взялся образ, ради двух строк не стоит. Копия `&'static str`
из константы ничего не стоит.

## Поток

1. Проверить форму версии.
2. Подставить её в оба шаблона: URL образа и URL файла сумм.
3. GET на URL файла сумм с потолком тела 1 МиБ.
4. Найти в тексте строку ровно с нашим именем файла, взять сумму.
5. Вернуть `ResolvedImage`.

Ни кеша списка сумм, ни публикации прогресса, ни флага отмены: это единицы
килобайт по одному запросу, а не сотни мегабайт потоком. Список сумм не
кешируется и потому, что он и есть источник актуальности — закешированный, он
через месяц указывал бы на сумму снятой с публикации сборки.

Потолок тела обязателен: без него сервер вправе отдать гигабайт прямо в память
рабочего потока. Мегабайта хватает с запасом — боевой файл занимает 7843 байта
(факт 2).

## Разбор `SHA256SUMS`

```rust
fn parse_sha256sums(text: &str, file_name: &str) -> Result<String, ResolveError>;
```

Строка разбирается как сумма и имя, разделённые пробелами; ведущая `*` у имени
отбрасывается. Сумма обязана быть 64 hex-символами — иначе строка не считается
разобранной.

Имя сравнивается **целиком**, а не по префиксу. В боевом файле рядом с
`ubuntu-24.04-server-cloudimg-amd64.img` лежат `...-amd64.img.manifest`,
`...-amd64.squashfs.manifest` и ещё полдюжины имён с тем же началом; сравнение по
префиксу вернуло бы сумму манифеста, и авария случилась бы только после загрузки
шестисот мегабайт.

Различие двух исходов намеренное:

* ни одна строка не разобралась — `MalformedChecksums`. Типичный случай: сервер
  отдал HTML-страницу ошибки со статусом 200.
* строки разобрались, но нашего имени среди них нет — `ImageNotListed`. Значит
  такого релиза или такой сборки у Canonical нет.

Пользователю это разные новости, и валить их в один вариант значит терять
единственную полезную часть диагностики.

## Ошибки

Свой `ResolveError` с `Display` и `std::error::Error`, по образцу `DownloadError`
(`crates/image/src/error.rs`). Никаких `anyhow` и `Box<dyn Error>`.

```rust
pub enum ResolveError {
    InvalidRelease(String),
    Http(String),
    UnexpectedStatus { status: u16 },
    MalformedChecksums { url: String },
    ImageNotListed { file_name: String, url: String },
}
```

Отдельный enum, а не расширение `DownloadError`: у них разные вызывающие и разные
вопросы к пользователю. «Сервер не отдал список сумм для 24.04» и «скачанный
образ не сошёлся с суммой» — разные аварии, и в общем enum'е каждый вызывающий
матчил бы варианты, которых у него не бывает. Цена — два дублирующихся по смыслу
варианта `Http` и `UnexpectedStatus`; это дешевле общего надтипа над двумя
несвязанными наборами отказов.

Перед возвратом ошибка пишется в `log::error!`, как везде в крейте.

## Логирование

Уровни DEBUG..ERROR, `TRACE` не используется.

* DEBUG — URL файла сумм и число разобранных строк.
* INFO — итог: профиль, версия, URL образа и его сумма.
* WARN — строки, которые не разобрались, при том что другие разобрались.
* ERROR — любая возвращаемая ошибка.

## Тестирование

Чистые функции — прямыми unit-тестами:

* форма версии: `"24.04"` и `"22.04"` принимаются; `""`, `"noble"`, `"24"`,
  `"24.4"`, `"24.04/../.."`, `"../../etc"`, `"24.04 "` с пробелом — отвергаются;
* сборка обоих URL из шаблонов профиля;
* разбор: запись со звёздочкой и без неё; имя-префикс (`.img` не матчится на
  `.img.manifest`); мусор вместо суммы; отсутствие искомого имени; пустой текст;
* тот же разбор на фикстуре настоящего файла через `include_str!`.

Фикстура — `crates/image/tests/fixtures/ubuntu-24.04-SHA256SUMS`, обрезанная до
пары десятков строк: полный файл на 8 КБ в репозитории лишний, а все интересные
случаи (наш образ, его манифесты, чужие архитектуры) укладываются в этот срез.

Сеть — интеграционным тестом на петлевом `TcpListener` из существующего
`crates/image/tests/support/mod.rs`: сервер отдаёт фикстуру, резолвер возвращает
ожидаемые URL и сумму; и второй случай — 404 даёт `UnexpectedStatus`. Базовый URL
берётся из `DistroProfile`, который тест собирает сам с адресом петлевого
сервера, — поэтому подмены транспорта и трейта-заглушки над HTTP не требуется.

Теста, ходящего на настоящий `cloud-images.ubuntu.com`, нет намеренно: он зелёный
ровно до следующей публикации Canonical, а сверх петлевого проверяет лишь
доступность чужого сервера. Факты о нём проверены экспериментом на этапе дизайна
и записаны выше.

## Вне объёма

* Остальные дистрибутивы: Fedora, Debian и их форматы файлов сумм — отдельная
  задача.
* Кодовые имена релизов как вход.
* Выбор архитектуры, отличной от amd64.
* Каталог доступных релизов и его показ в UI.
* Оркестрация «резолвни и скачай»: её заводит тот, у кого появится вызывающий.
* Проверка GPG-подписей — за пределами эпика.
* Кеширование файла контрольных сумм.
